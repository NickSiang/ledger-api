# 個人記帳本資料表設計（PostgreSQL on Supabase）

本文件定義個人記帳本資料庫的所有資料表結構、欄位規範、關聯約束、派生數值計算邏輯（帳戶餘額、持有股數、平均成本、統一發票期別）與驗證分工。

---

## 全域設計共通規範

1. **主鍵（Primary Key）**
   - 每一張表的主鍵皆命名為 `id`，型別為 64 位元整數（`bigint`），由資料庫自動遞增產生且建立後不可修改（對應 PostgreSQL 之 Identity 機制，並由 API 在寫入前檢查禁止更新 `id`）。
2. **外鍵（Foreign Key）與刪除保護**
   - 所有外鍵預設皆採用「父列仍被參照時禁止刪除」（對應 PostgreSQL 外鍵之限制刪除約束 `RESTRICT`）。
   - **唯一例外**：`invoice_items.invoice_id` 指向 `invoices.id` 採用「隨父列一併刪除」（對應 PostgreSQL 外鍵之連帶刪除約束 `CASCADE`），使發票品項跟著發票一起消失。
   - 本系統日常帳務不提供刪除帳務列之功能（由 API 在寫入前檢查，不開放刪除端點）。
3. **時間戳記（Timestamps）**
   - 所有時間欄位一律採用含時區之時間戳記型別 `timestamptz`。
   - 每一張表皆包含 `created_at` 與 `updated_at` 兩個必填欄位：
     - `created_at`：型別 `timestamptz`，必填（`NOT NULL`），在插入資料列時由資料庫自動填入當下 UTC 時間。
     - `updated_at`：型別 `timestamptz`，必填（`NOT NULL`），初次插入與後續每次更新時皆由後端應用程式（Flask / SQLAlchemy）寫入當下 UTC 時間。
4. **金額、幣別與匯率**
   - 所有金額、單價、股數、匯率皆採用可含小數之精確數值型別 `numeric`（例如金額用 `numeric(18, 4)`、股數用 `numeric(18, 6)`、匯率用 `numeric(18, 6)`），避免浮點數誤差。
   - 幣別欄位統一使用三碼大寫英文（型別 `char(3)`，PostgreSQL `CHECK` 約束限制為三個大寫英文字母 `^[A-Z]{3}$`）。
   - 每一筆涉及金額的帳務紀錄皆儲存 `currency_code`（交易原幣別）與 `exchange_rate_to_twd`（換算為台幣 TWD 之匯率）：
     - PostgreSQL `CHECK` 約束：`exchange_rate_to_twd > 0`。
     - PostgreSQL `CHECK` 約束：當 `currency_code = 'TWD'` 時，`exchange_rate_to_twd = 1`；當 `currency_code <> 'TWD'` 時，必填實際匯率且大於 0。

---

## 資料表總覽

本設計共包含 11 張資料表，涵蓋帳戶與移轉、入帳冊、花費冊、發票冊、投資冊：

1. `accounts`：資金與信用帳戶
2. `account_transfers`：帳戶間資金移轉紀錄
3. `income_categories`：入帳分類
4. `expense_categories`：花費分類
5. `invoices`：台灣統一發票主檔
6. `invoice_items`：統一發票品項明細
7. `invoice_prize_schedules`：統一發票各期開獎獎別與獎金表
8. `investment_securities`：投資標的檔
9. `investment_transactions`：投資交易紀錄
10. `incomes`：入帳紀錄
11. `expenses`：花費紀錄

## 各資料表詳細設計

### 1. `accounts`（帳戶表）

#### 表在記什麼，以及為什麼要單獨成表
記錄個人名下所有錢包與資金載體，包含現金、銀行帳戶、信用卡、券商交割戶。單獨成表是因為所有入帳、花費、帳戶移轉與投資交割都必須歸屬到特定帳戶，才能統一管理各帳戶的幣別、初始資金，並作為計算各帳戶即時餘額的基準。

#### 欄位清單

| 欄位名稱 | 型別 | 必填 / 可空 | 唯一性 | 說明與外鍵指向 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `bigint` | 必填 | 唯一（主鍵） | 資料庫自動產生、建立後不可改的整數主鍵 |
| `name` | `varchar(100)` | 必填 | 不可重複 | 帳戶名稱（例如：錢包現金、台新主帳戶、國泰信用卡、永豐交割戶） |
| `account_type` | `varchar(30)` | 必填 | 可重複 | 帳戶種類：`cash`（現金）、`bank`（銀行）、`credit_card`（信用卡）、`brokerage_settlement`（券商交割戶） |
| `currency_code` | `char(3)` | 必填 | 可重複 | 帳戶基準幣別（三碼大寫英文，如 `TWD`、`USD`、`JPY`） |
| `initial_balance` | `numeric(18, 4)` | 必填 | 可重複 | 開帳初始金額（原幣別），預設為 `0` |
| `initial_exchange_rate_to_twd` | `numeric(18, 6)` | 必填 | 可重複 | 開帳初始金額換算台幣之匯率；若 `currency_code = 'TWD'` 則固定為 `1` |
| `note` | `text` | 可空 | 可重複 | 備註說明 |
| `created_at` | `timestamptz` | 必填 | 可重複 | 插入時由資料庫自動填入 UTC 時間 |
| `updated_at` | `timestamptz` | 必填 | 可重複 | 新增與更新時由程式寫入 UTC 時間 |

#### 規則與約束驗證方式
- **PostgreSQL 約束**：
  - `id` 為自動產生之主鍵（Identity）。
  - `name` 設定 `UNIQUE` 約束，確保帳戶名稱不重複。
  - `account_type` 設定 `CHECK` 約束，僅允許 `'cash'`、`'bank'`、`'credit_card'`、`'brokerage_settlement'` 四種值。
  - `currency_code` 設定 `CHECK` 約束，符合三碼大寫英文格式。
  - `initial_exchange_rate_to_twd` 設定 `CHECK` 約束：必須大於 `0`，且當 `currency_code = 'TWD'` 時必須等於 `1`。
- **由 API 在寫入前檢查**：
  - 更新時禁止修改 `id`、`created_at`；若帳戶已有關聯帳務紀錄，禁止變更 `currency_code` 與 `account_type`。

### 2. `account_transfers`（帳戶移轉表）

#### 表在記什麼，以及為什麼要單獨成表
記錄資金從一個帳戶轉出至另一個帳戶的行為（例如：從銀行領現放入錢包、從銀行轉帳繳信用卡費、從銀行轉入券商交割戶、或跨幣別換匯轉帳）。單獨成表是因為移轉屬於內部資金調度，既不是「入帳（資產淨增加）」也不是「花費（資產淨消耗）」，若混入入帳或花費表會導致收支統計失真。

#### 欄位清單

| 欄位名稱 | 型別 | 必填 / 可空 | 唯一性 | 說明與外鍵指向 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `bigint` | 必填 | 唯一（主鍵） | 資料庫自動產生、建立後不可改的整數主鍵 |
| `from_account_id` | `bigint` | 必填 | 可重複 | 轉出帳戶，外鍵指向 `accounts.id`（父列被參照時禁止刪除 `RESTRICT`） |
| `to_account_id` | `bigint` | 必填 | 可重複 | 轉入帳戶，外鍵指向 `accounts.id`（父列被參照時禁止刪除 `RESTRICT`） |
| `transferred_at` | `timestamptz` | 必填 | 可重複 | 移轉發生時間 |
| `from_amount` | `numeric(18, 4)` | 必填 | 可重複 | 轉出帳戶扣減金額（依轉出帳戶幣別） |
| `from_currency_code` | `char(3)` | 必填 | 可重複 | 轉出幣別（三碼大寫英文） |
| `from_exchange_rate_to_twd` | `numeric(18, 6)` | 必填 | 可重複 | 轉出金額換成台幣的匯率（`TWD` 為 `1`） |
| `to_amount` | `numeric(18, 4)` | 必填 | 可重複 | 轉入帳戶增加金額（依轉入帳戶幣別；同幣別移轉時等於 `from_amount`） |
| `to_currency_code` | `char(3)` | 必填 | 可重複 | 轉入幣別（三碼大寫英文） |
| `to_exchange_rate_to_twd` | `numeric(18, 6)` | 必填 | 可重複 | 轉入金額換成台幣的匯率（`TWD` 為 `1`） |
| `fee_amount` | `numeric(18, 4)` | 必填 | 可重複 | 轉帳手續費（由轉出帳戶額外扣減，無手續費時填 `0`） |
| `note` | `text` | 可空 | 可重複 | 移轉備註（如：換匯、繳卡費、提款） |
| `created_at` | `timestamptz` | 必填 | 可重複 | 插入時由資料庫自動填入 UTC 時間 |
| `updated_at` | `timestamptz` | 必填 | 可重複 | 新增與更新時由程式寫入 UTC 時間 |

#### 規則與約束驗證方式
- **PostgreSQL 約束**：
  - `from_account_id <> to_account_id`（`CHECK` 約束，禁止同一帳戶轉給自己）。
  - `from_amount > 0`、`to_amount > 0`、`fee_amount >= 0`（`CHECK` 約束）。
  - `from_exchange_rate_to_twd > 0` 且當 `from_currency_code = 'TWD'` 時等於 `1`（`CHECK` 約束）。
  - `to_exchange_rate_to_twd > 0` 且當 `to_currency_code = 'TWD'` 時等於 `1`（`CHECK` 約束）。
  - 當 `from_currency_code = to_currency_code` 時，`from_amount = to_amount`（`CHECK` 約束）。
- **由 API 在寫入前檢查**：
  - 檢查 `from_currency_code` 必須與 `from_account_id` 在 `accounts` 表的 `currency_code` 一致；`to_currency_code` 必須與 `to_account_id` 在 `accounts` 表的 `currency_code` 一致。

### 3. `income_categories`（入帳分類表）

#### 表在記什麼，以及為什麼要單獨成表
記錄入帳的分類項目（例如：薪水、獎金、利息、退款、發票中獎、股利收入、減資退還）。單獨成表且與花費分類分開，是因為入帳與花費語意截然不同，分開建表可由資料庫外鍵直接確保入帳紀錄不會誤掛花費分類，且分類名稱可獨立管理與擴充。

#### 欄位清單

| 欄位名稱 | 型別 | 必填 / 可空 | 唯一性 | 說明與外鍵指向 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `bigint` | 必填 | 唯一（主鍵） | 資料庫自動產生、建立後不可改的整數主鍵 |
| `name` | `varchar(50)` | 必填 | 不可重複 | 入帳分類名稱 |
| `description` | `text` | 可空 | 可重複 | 分類說明 |
| `created_at` | `timestamptz` | 必填 | 可重複 | 插入時由資料庫自動填入 UTC 時間 |
| `updated_at` | `timestamptz` | 必填 | 可重複 | 新增與更新時由程式寫入 UTC 時間 |

#### 規則與約束驗證方式
- **PostgreSQL 約束**：
  - `name` 設定 `UNIQUE` 約束，且 `CHECK (btrim(name) <> '')` 禁止空白字串。

### 5. `invoices`（台灣統一發票主檔表）

#### 表在記什麼，以及為什麼要單獨成表
記錄台灣統一發票的票面主體資訊（發票號碼、開立時間、期別、賣方統編與名稱、發票總額、對獎狀態與中獎獎別）。單獨成表是因為發票既是對獎與留底的憑證，又與花費呈現「一張發票可對應多筆花費，且花費合計不必等於發票總額（例如代墊、折扣、分攤）」的關係，同時也是發票品項的父表與中獎入帳的來源。

#### 欄位清單

| 欄位名稱 | 型別 | 必填 / 可空 | 唯一性 | 說明與外鍵指向 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `bigint` | 必填 | 唯一（主鍵） | 資料庫自動產生、建立後不可改的整數主鍵 |
| `invoice_number` | `char(10)` | 必填 | 與 `period_code` 複合不可重複 | 統一發票號碼：兩碼大寫英文加八碼數字（如 `AB12345678`） |
| `issued_at` | `timestamptz` | 必填 | 可重複 | 發票開立時間 |
| `period_code` | `varchar(10)` | 必填 | 與 `invoice_number` 複合不可重複 | 所屬統一發票期別代碼（格式如 `115-1112`，代表民國 115 年 11-12 月期） |
| `seller_name` | `varchar(100)` | 可空 | 可重複 | 賣方商家名稱 |
| `seller_tax_id` | `char(8)` | 可空 | 可重複 | 賣方統一編號（八碼數字） |
| `currency_code` | `char(3)` | 必填 | 可重複 | 發票幣別（台灣統一發票預設為 `TWD`） |
| `exchange_rate_to_twd` | `numeric(18, 6)` | 必填 | 可重複 | 換成台幣之匯率（`TWD` 時為 `1`） |
| `total_amount` | `numeric(18, 4)` | 必填 | 可重複 | 發票票面總金額 |
| `winning_prize_schedule_id` | `bigint` | 可空 | 可重複 | 若中獎，指向所屬期別中獎獎項 `invoice_prize_schedules.id`（外鍵 `RESTRICT`） |
| `note` | `text` | 可空 | 可重複 | 發票備註 |
| `created_at` | `timestamptz` | 必填 | 可重複 | 插入時由資料庫自動填入 UTC 時間 |
| `updated_at` | `timestamptz` | 必填 | 可重複 | 新增與更新時由程式寫入 UTC 時間 |

#### 統一發票期別如何由開立日決定
台灣統一發票以「台灣時間（`Asia/Taipei`, UTC+8）之開立日（`issued_at`）」決定所屬期別：
1. **計算民國年（`roc_year`）**：取 `issued_at` 轉換為 `Asia/Taipei` 時區後的西元年份 `year`，計算 `roc_year = year - 1911`。
2. **計算雙月期別（`start_month`, `end_month`）**：統一發票每兩個月為一期（01-02 月、03-04 月、05-06 月、07-08 月、09-10 月、11-12 月）。取 `issued_at` 在 `Asia/Taipei` 時區的月份 `month`（1 至 12）：
   - 若 `month` 為奇數：起始月 `start_month = month`，結束月 `end_month = month + 1`。
   - 若 `month` 為偶數：起始月 `start_month = month - 1`，結束月 `end_month = month`。
3. **組成期別代碼 `period_code`**：將民國年與補零後之起迄雙月組合為 `{roc_year}-{start_month:02d}{end_month:02d}`（例如：西元 2026 年 11 月 12 日開立，民國年為 `115`，雙月為 `1112`，期別即為 `115-1112`）。

#### 規則與約束驗證方式
- **PostgreSQL 約束**：
  - `invoice_number` 設定正規表示式 `CHECK` 約束：`invoice_number ~ '^[A-Z]{2}[0-9]{8}$'`（強制兩碼大寫英文加八碼數字）。
  - `(period_code, invoice_number)` 設定複合 `UNIQUE` 約束，確保同一期別內發票號碼絕對不重複。
  - `period_code` 設定正規表示式 `CHECK` 約束：符合 `^[0-9]{3}-(0102|0304|0506|0708|0910|1112)$`，且可透過以 `issued_at AT TIME ZONE 'Asia/Taipei'` 計算之 `CHECK` 約束（或產生欄位）強制 `period_code` 必須與 `issued_at` 推導結果完全一致。
  - `seller_tax_id` 若非空，設定 `CHECK` 約束：`seller_tax_id ~ '^[0-9]{8}$'`。
  - `total_amount >= 0`（`CHECK` 約束）。
  - `exchange_rate_to_twd > 0` 且當 `currency_code = 'TWD'` 時等於 `1`（`CHECK` 約束）。
- **由 API 在寫入前檢查**：
  - 寫入或更新 `issued_at` 時，自動依上述公式算出 `period_code` 並驗證與 `winning_prize_schedule_id` 所屬的 `period_code` 相符。

### 6. `invoice_items`（發票品項表）

#### 表在記什麼，以及為什麼要單獨成表
記錄一張統一發票上的各個購買品項明細（品名、數量、單價、小計）。單獨成表是因為一張發票可包含一至多個品項（一對多關係），拆分為子表才能符合正規化並支援逐項查詢與核對。

#### 欄位清單

| 欄位名稱 | 型別 | 必填 / 可空 | 唯一性 | 說明與外鍵指向 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `bigint` | 必填 | 唯一（主鍵） | 資料庫自動產生、建立後不可改的整數主鍵 |
| `invoice_id` | `bigint` | 必填 | 與 `line_number` 複合不可重複 | 所屬發票，外鍵指向 `invoices.id`（**唯一例外：父列刪除時連帶刪除 `ON DELETE CASCADE`**） |
| `line_number` | `integer` | 必填 | 與 `invoice_id` 複合不可重複 | 品項在該張發票上的項次序號（從 1 開始） |
| `item_name` | `varchar(200)` | 必填 | 可重複 | 品項名稱 |
| `quantity` | `numeric(18, 4)` | 必填 | 可重複 | 數量 |
| `unit_price` | `numeric(18, 4)` | 必填 | 可重複 | 單價 |
| `subtotal_amount` | `numeric(18, 4)` | 必填 | 可重複 | 該品項小計金額（可含折讓或尾差） |
| `created_at` | `timestamptz` | 必填 | 可重複 | 插入時由資料庫自動填入 UTC 時間 |
| `updated_at` | `timestamptz` | 必填 | 可重複 | 新增與更新時由程式寫入 UTC 時間 |

#### 規則與約束驗證方式
- **PostgreSQL 約束**：
  - `invoice_id` 外鍵指向 `invoices.id`，設定 `ON DELETE CASCADE`（當發票被刪除時，其下所有品項跟著發票一起消失）。
  - `(invoice_id, line_number)` 設定複合 `UNIQUE` 約束，避免同一張發票出現重複項次。
  - `line_number >= 1`、`quantity > 0`（`CHECK` 約束）。

### 7. `invoice_prize_schedules`（統一發票開獎獎別與獎金表）

#### 表在記什麼，以及為什麼要單獨成表
記錄台灣統一發票每一期的開獎號碼規則、獎別名稱（如特別獎、特獎、頭獎、二獎、三獎、四獎、五獎、六獎、雲端發票專屬獎）以及各獎別對應的獎金金額。單獨成表是為了將開獎獎金與對獎規則儲存在資料表中，不寫死在程式碼或設計說明的程式片段裡，未來財政部調整增開獎項或獎金時可直接透過資料列維護。

### 9. `investment_transactions`（投資交易表）

#### 表在記什麼，以及為什麼要單獨成表
記錄針對某一檔投資標的發生的每一筆交易與股權異動事件。單獨成表是因為投資部位的持有股數、累積投入成本與平均成本皆由歷史交易序列推導算出，且不同交易種類（買進、賣出、現金股利、配股、股息再投入、分割、合併、減資）對股數、成本與交割戶資金各有明確的影響規則。

#### 欄位清單

| 欄位名稱 | 型別 | 必填 / 可空 | 唯一性 | 說明與外鍵指向 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `bigint` | 必填 | 唯一（主鍵） | 資料庫自動產生、建立後不可改的整數主鍵 |
| `security_id` | `bigint` | 必填 | 可重複 | 投資標的，外鍵指向 `investment_securities.id`（`RESTRICT`） |
| `settlement_account_id` | `bigint` | 可空 | 可重複 | 交割扣款帳戶，外鍵指向 `accounts.id`（`RESTRICT`）。買進、賣出必填；純股數異動（配股、分割、合併、無退現減資）可空；現金股利與減資退現則透過 `incomes` 表入帳 |
| `transaction_type` | `varchar(30)` | 必填 | 可重複 | 交易種類，見下方 8 種列舉值 |
| `transacted_at` | `timestamptz` | 必填 | 可重複 | 交易成交或除權息生效時間 |
| `settled_at` | `timestamptz` | 可空 | 可重複 | 交割款實際扣款或入帳時間（若無交割款移動可空） |
| `shares_delta` | `numeric(18, 6)` | 必填 | 可重複 | 股數增減量（增加為正數、減少為負數、純現金股利為 `0`） |
| `unit_price` | `numeric(18, 6)` | 可空 | 可重複 | 每股成交單價或再投入單價（分割、合併、純配股可空） |
| `gross_amount` | `numeric(18, 4)` | 必填 | 可重複 | 交易總價金或現金股利／減資退現總額（無金額變動之股權事件填 `0`） |
| `fee_amount` | `numeric(18, 4)` | 必填 | 可重複 | 手續費（無則填 `0`） |
| `tax_amount` | `numeric(18, 4)` | 必填 | 可重複 | 交易稅或股利預扣稅額（無則填 `0`） |
| `net_settlement_amount` | `numeric(18, 4)` | 必填 | 可重複 | 對交割帳戶造成的淨現金變動絕對值（買進為總支出 `gross + fee + tax`；賣出為淨收回 `gross - fee - tax`；其餘不直接由本表扣減交割戶者填 `0`） |
| `currency_code` | `char(3)` | 必填 | 可重複 | 交易幣別（三碼大寫英文） |
| `exchange_rate_to_twd` | `numeric(18, 6)` | 必填 | 可重複 | 換成台幣之匯率（`TWD` 時為 `1`） |
| `note` | `text` | 可空 | 可重複 | 交易備註（例如分割比例、減資比例說明） |
| `created_at` | `timestamptz` | 必填 | 可重複 | 插入時由資料庫自動填入 UTC 時間 |
| `updated_at` | `timestamptz` | 必填 | 可重複 | 新增與更新時由程式寫入 UTC 時間 |

#### 支援的 8 種投資交易種類與欄位約束
`transaction_type` 支援以下 8 種值，並由 PostgreSQL `CHECK` 約束強制各種類對應之正負號與必填規則：

1. `buy`（買進）：`shares_delta > 0`、`settlement_account_id IS NOT NULL`、`unit_price >= 0`、`net_settlement_amount = gross_amount + fee_amount + tax_amount`。
2. `sell`（賣出）：`shares_delta < 0`、`settlement_account_id IS NOT NULL`、`unit_price >= 0`、`net_settlement_amount = gross_amount - fee_amount - tax_amount`。
3. `cash_dividend`（現金股利）：`shares_delta = 0`、`gross_amount > 0`、`net_settlement_amount = 0`（實際收到的現金透過一筆關聯此交易的 `incomes` 入帳紀錄進入帳戶，避免重複計入帳戶餘額）。
4. `stock_dividend`（配股）：`shares_delta > 0`、`gross_amount = 0`、`net_settlement_amount = 0`。
5. `dividend_reinvestment`（股息再投入）：`shares_delta > 0`、`gross_amount > 0`、`unit_price > 0`、`net_settlement_amount = 0`（股息直接轉為股數與投入成本，不經過交割帳戶現金增減）。
6. `split`（分割）：`shares_delta > 0`、`gross_amount = 0`、`net_settlement_amount = 0`（股數增加，總投入成本不變）。
7. `reverse_split`（合併）：`shares_delta < 0`、`gross_amount = 0`、`net_settlement_amount = 0`（股數減少，總投入成本不變）。
8. `capital_reduction`（減資）：`shares_delta < 0`、`gross_amount >= 0`、`net_settlement_amount = 0`（彌補虧損減資時 `gross_amount = 0`；現金減資退回股款時 `gross_amount > 0`，且退回的現金透過一筆關聯此交易的 `incomes` 入帳紀錄進入帳戶）。

#### 規則與約束驗證方式
- **PostgreSQL 約束**：
  - `transaction_type` 列舉值與對應的 `shares_delta`、`settlement_account_id`、`gross_amount`、`net_settlement_amount` 組合設定 `CHECK` 約束（如上表所列）。
  - `fee_amount >= 0`、`tax_amount >= 0`、`gross_amount >= 0`、`net_settlement_amount >= 0`（`CHECK` 約束）。
  - `exchange_rate_to_twd > 0` 且當 `currency_code = 'TWD'` 時等於 `1`（`CHECK` 約束）。
- **由 API 在寫入前檢查**：
  - **賣出（以及合併、減資等減少股數之交易）不得使持有股數小於 0**：API 在寫入或更新交易前，鎖定該 `security_id` 的交易紀錄，依 `transacted_at`（及 `id`）時間順序累計 `shares_delta`，驗證在該筆交易發生當下及之後所有時間點的累計持有股數皆 `>= 0`，若會導致任何時點持有股數 `< 0` 則拒絕寫入（亦可在 PostgreSQL 搭配 Trigger 雙重把關）。
  - 若 `settlement_account_id` 非空，檢查該帳戶的 `account_type` 為 `'brokerage_settlement'`（或允許之交割帳戶）且幣別相符。

### 10. `incomes`（入帳表）

#### 表在記什麼，以及為什麼要單獨成表
記錄每一筆進入帳戶的實質資金收入，例如薪水、獎金、利息、退款、統一發票中獎獎金、以及投資產生的現金股利與減資退回現金。單獨成表是因為入帳代表個人淨資產的正向流入，且需支援與統一發票（中獎獎金）及投資交易（現金股利／減資退現）的一對一溯源關聯。

#### 欄位清單

| 欄位名稱 | 型別 | 必填 / 可空 | 唯一性 | 說明與外鍵指向 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `bigint` | 必填 | 唯一（主鍵） | 資料庫自動產生、建立後不可改的整數主鍵 |
| `account_id` | `bigint` | 必填 | 可重複 | 入帳目標帳戶，外鍵指向 `accounts.id`（`RESTRICT`） |
| `category_id` | `bigint` | 必填 | 可重複 | 入帳分類，外鍵指向 `income_categories.id`（`RESTRICT`） |
| `received_at` | `timestamptz` | 必填 | 可重複 | 實際入帳時間 |
| `amount` | `numeric(18, 4)` | 必填 | 可重複 | 入帳金額（原幣別） |
| `currency_code` | `char(3)` | 必填 | 可重複 | 幣別（三碼大寫英文） |
| `exchange_rate_to_twd` | `numeric(18, 6)` | 必填 | 可重複 | 換成台幣之匯率（`TWD` 時為 `1`） |
| `invoice_id` | `bigint` | 可空 | **非空時不可重複（UNIQUE）** | 若為發票中獎獎金，外鍵指向 `invoices.id`（`RESTRICT`）；一張發票最多對應一筆入帳 |
| `investment_transaction_id` | `bigint` | 可空 | **非空時不可重複（UNIQUE）** | 若為現金股利或減資退回現金，外鍵指向 `investment_transactions.id`（`RESTRICT`）；一筆交易最多對應一筆入帳 |
| `description` | `varchar(200)` | 必填 | 可重複 | 入帳摘要（如：11月薪資、台積電現金股利、發票六獎） |
| `note` | `text` | 可空 | 可重複 | 詳細備註 |
| `created_at` | `timestamptz` | 必填 | 可重複 | 插入時由資料庫自動填入 UTC 時間 |
| `updated_at` | `timestamptz` | 必填 | 可重複 | 新增與更新時由程式寫入 UTC 時間 |

#### 規則與約束驗證方式
- **PostgreSQL 約束**：
  - `amount > 0`（`CHECK` 約束）。
  - `exchange_rate_to_twd > 0` 且當 `currency_code = 'TWD'` 時等於 `1`（`CHECK` 約束）。
  - `invoice_id` 設定 `UNIQUE` 約束（PostgreSQL 的 `UNIQUE` 允許有多筆 `NULL`，但非 `NULL` 值不可重複），強制「一張發票最多記成一筆中獎入帳」。
  - `investment_transaction_id` 設定 `UNIQUE` 約束，強制「一筆投資交易最多記成一筆入帳」。
  - 設定 `CHECK` 約束：`NOT (invoice_id IS NOT NULL AND investment_transaction_id IS NOT NULL)`，確保同一筆入帳不會同時既是發票中獎又是投資配息／減資。
- **由 API 在寫入前檢查**：
  - 當 `invoice_id` 非空時，檢查該發票的 `winning_prize_schedule_id` 非空（確實有中獎），並核對入帳金額與 `invoice_prize_schedules.prize_amount`（或扣稅後金額）。
  - 當 `investment_transaction_id` 非空時，檢查對應之 `investment_transactions.transaction_type` 必須為 `'cash_dividend'` 或 `'capital_reduction'`（且 `gross_amount > 0`）。
  - 檢查 `currency_code` 與 `account_id` 所屬帳戶的 `currency_code` 一致。

### 11. `expenses`（花費表）

#### 表在記什麼，以及為什麼要單獨成表
記錄每一筆從帳戶支出的消費行為。單獨成表是因為花費需要獨立區分「消費發生日（`spent_at`）」與「實際扣款／信用卡結算扣款日（`deducted_at`）」，且需支援「多筆花費對應同一張統一發票，且花費合計不必等於發票總額」的彈性對帳結構。

#### 欄位清單

| 欄位名稱 | 型別 | 必填 / 可空 | 唯一性 | 說明與外鍵指向 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `bigint` | 必填 | 唯一（主鍵） | 資料庫自動產生、建立後不可改的整數主鍵 |
| `account_id` | `bigint` | 必填 | 可重複 | 支付帳戶（現金、銀行或信用卡），外鍵指向 `accounts.id`（`RESTRICT`） |
| `category_id` | `bigint` | 必填 | 可重複 | 花費分類，外鍵指向 `expense_categories.id`（`RESTRICT`） |
| `invoice_id` | `bigint` | 可空 | 可重複 | 關聯的統一發票，外鍵指向 `invoices.id`（`RESTRICT`）。可空，且允許同一 `invoice_id` 對到多筆花費 |
| `spent_at` | `timestamptz` | 必填 | 可重複 | 實際消費發生時間（消費日） |
| `deducted_at` | `timestamptz` | 可空 | 可重複 | 實際扣款或信用卡帳單扣款時間；現金／簽帳金融卡可與 `spent_at` 相同，信用卡可晚於 `spent_at` 或待出帳後填入 |
| `amount` | `numeric(18, 4)` | 必填 | 可重複 | 花費金額（原幣別） |
| `currency_code` | `char(3)` | 必填 | 可重複 | 幣別（三碼大寫英文） |
| `exchange_rate_to_twd` | `numeric(18, 6)` | 必填 | 可重複 | 換成台幣之匯率（`TWD` 時為 `1`） |
| `description` | `varchar(200)` | 必填 | 可重複 | 花費摘要 |
| `note` | `text` | 可空 | 可重複 | 備註（如：與朋友分攤、含折扣） |
| `created_at` | `timestamptz` | 必填 | 可重複 | 插入時由資料庫自動填入 UTC 時間 |
| `updated_at` | `timestamptz` | 必填 | 可重複 | 新增與更新時由程式寫入 UTC 時間 |

#### 規則與約束驗證方式
- **PostgreSQL 約束**：
  - `amount > 0`（`CHECK` 約束）。
  - `exchange_rate_to_twd > 0` 且當 `currency_code = 'TWD'` 時等於 `1`（`CHECK` 約束）。
  - `deducted_at IS NULL OR deducted_at >= spent_at`（`CHECK` 約束，扣款時間不得早於消費發生時間）。
  - `invoice_id` 不設唯一約束，亦不限制相同 `invoice_id` 的 `SUM(amount)` 等於 `invoices.total_amount`，直接支援「一張發票對到多筆花費，且花費合計不必等於發票總額」。
- **由 API 在寫入前檢查**：
  - 檢查 `currency_code` 與 `account_id` 所屬帳戶的 `currency_code` 一致（若外幣刷台幣信用卡，則以折算後帳單幣別或原幣加上匯率記錄）。

## 派生數值計算邏輯（不設為可修改欄位）

為確保資料絕對一致、不會發生帳務明細與總數兜不攏的情況，**帳戶餘額**、**標的持有股數**與**標的持有平均成本**均不設為資料表中的可修改欄位，而是由相關資料列即時聚合計算（或透過資料庫 View 呈現）：

### 1. 帳戶餘額（Account Balance）如何算出
針對任一帳戶 `A`（對應 `accounts.id`），其目前原幣別餘額由以下 5 個來源的資料列加減算出：

1. **初始金額（正向基準）**：
   - 取 `accounts` 表中 `id = A` 的 `initial_balance`。
2. **入帳總和（加項）**：
   - 加總 `incomes` 表中所有 `account_id = A` 的 `amount`（包含一般收入、發票中獎入帳、現金股利入帳、減資退現入帳）。
3. **花費總和（減項）**：
   - 減去 `expenses` 表中所有 `account_id = A` 的 `amount`。
   - *(註：對現金與銀行帳戶而言，餘額為實質存款餘額；對信用卡帳戶而言，花費為負向累積應付帳款，當從銀行帳戶透過 `account_transfers` 轉入信用卡帳戶繳卡費時，信用卡帳戶餘額即回沖歸零。若需區分「已入帳扣款餘額」與「含未扣款總刷卡額」，可依 `expenses.deducted_at IS NOT NULL` 篩選。)*
4. **帳戶移轉（轉入為加項、轉出與手續費為減項）**：
   - **轉入加項**：加總 `account_transfers` 表中所有 `to_account_id = A` 的 `to_amount`。
   - **轉出減項**：減去 `account_transfers` 表中所有 `from_account_id = A` 的 `(from_amount + fee_amount)`。
5. **投資交割款（賣出交割為加項、買進交割為減項）**：
   - **買進扣款減項**：減去 `investment_transactions` 表中所有 `settlement_account_id = A` 且 `transaction_type = 'buy'` 的 `net_settlement_amount`。
   - **賣出收款加項**：加總 `investment_transactions` 表中所有 `settlement_account_id = A` 且 `transaction_type = 'sell'` 的 `net_settlement_amount`。
   - *(註：`cash_dividend` 與 `capital_reduction` 的現金流入已經記在 `incomes` 表中，故不重複從 `investment_transactions` 加計。)*

> **計算公式總結**：
> `帳戶餘額 = accounts.initial_balance + SUM(incomes.amount) - SUM(expenses.amount) + SUM(account_transfers轉入.to_amount) - SUM(account_transfers轉出.from_amount + fee_amount) + SUM(investment_transactions賣出.net_settlement_amount) - SUM(investment_transactions買進.net_settlement_amount)`

---

### 2. 投資持有股數與平均成本如何算出
針對任一投資標的 `S`（對應 `investment_securities.id`），其持有股數與平均成本由 `investment_transactions` 表中 `security_id = S` 的所有資料列依 `(transacted_at ASC, id ASC)` 時間序列算出：

#### （1）持有股數（Current Holding Shares）
直接加總該標的所有交易列的股數變動量：
- `持有股數 = SUM(investment_transactions.shares_delta)`（其中 `security_id = S`）。
- 各交易種類對 `shares_delta` 的貢獻：
  - `buy`（買進）、`stock_dividend`（配股）、`dividend_reinvestment`（股息再投入）、`split`（分割）：`shares_delta > 0`（增加股數）。
  - `sell`（賣出）、`reverse_split`（合併）、`capital_reduction`（減資）：`shares_delta < 0`（減少股數）。
  - `cash_dividend`（現金股利）：`shares_delta = 0`（不影響股數）。

#### （2）持有總成本與平均成本（Total Cost Basis & Average Cost per Share）
採移動平均成本法（Moving Average Cost），將該標的之 `investment_transactions` 依 `(transacted_at ASC, id ASC)` 逐筆累計 `current_shares`（目前股數）與 `total_cost`（目前總成本，原幣別）：

- **初始狀態**：`current_shares = 0`、`total_cost = 0`。
- **遇到 `buy`（買進）**：
  - `total_cost = total_cost + gross_amount + fee_amount + tax_amount`
  - `current_shares = current_shares + shares_delta`
- **遇到 `dividend_reinvestment`（股息再投入）**：
  - `total_cost = total_cost + gross_amount + fee_amount + tax_amount`
  - `current_shares = current_shares + shares_delta`
- **遇到 `stock_dividend`（配股）、`split`（分割）、`reverse_split`（合併）**：
  - `total_cost` 保持不變（總投入成本不變，每股平均成本隨股數放大或縮小自動攤薄或提高）。
  - `current_shares = current_shares + shares_delta`
- **遇到 `sell`（賣出）**：
  - 按賣出股數佔賣出前持有股數之比例扣除對應成本：
  - `total_cost = total_cost * ((current_shares + shares_delta) / current_shares)`（註：`shares_delta` 為負數；若全數賣出使 `current_shares + shares_delta = 0`，則 `total_cost = 0`）。
  - `current_shares = current_shares + shares_delta`
- **遇到 `capital_reduction`（減資）**：
  - 若為彌補虧損減資（`gross_amount = 0`）：`total_cost` 不變，`current_shares = current_shares + shares_delta`。
  - 若為現金減資退回股款（`gross_amount > 0`）：將退回之股款自總成本中扣除（`total_cost = GREATEST(0, total_cost - gross_amount)`），且 `current_shares = current_shares + shares_delta`。
- **遇到 `cash_dividend`（現金股利）**：
  - 現金股利視為投資收益入帳，不改變 `current_shares` 與原始投入 `total_cost`。
- **最終每股平均成本**：
  - 當 `current_shares > 0` 時：`平均成本 = total_cost / current_shares`。
  - 當 `current_shares = 0` 時：`平均成本 = 0`。
  - 若需換算為台幣總成本，則在每筆增加成本之交易乘以其 `exchange_rate_to_twd` 後依相同比例原則累計。

## 這一次不建的表

依據專案範圍界定，以下功能與對應資料表在本次設計中**明確排除、不予建立**：

1. **預算相關表（Budgets）**：不做月度、年度或分類預算設定與超支警示表。
2. **固定收支／週期性帳務範本表（Recurring Transactions / Subscriptions）**：不做每月自動產生的固定扣款或固定入帳排程表。
3. **發票載具與自動匯入同步表（Invoice Carriers & Auto-Sync Logs）**：不建手機條碼、自然人憑證、會員載具綁定或財政部平台自動匯入紀錄表。
4. **即時或歷史市場股價表（Market Quotes / Security Prices）**：不建儲存外部即時股價或每日收盤價的資料表，目前僅記錄實際成交交易與成本。
5. **銀行同步與外部機構連線表（Bank Connections / Open Banking Sync）**：不建銀行 API 授權憑證或自動對帳匯入紀錄表。
6. **複式記帳分錄與會計科目表（Double-Entry Journal Entries & Chart of Accounts）**：不採借貸雙邊分錄表設計，以直觀的四本冊子（入帳、花費、投資、發票）搭配帳戶移轉表運作。
7. **帳務刪除紀錄或回收桶表（Deleted Records / Trash Bin）**：本系統不做刪除帳務列功能，也不建立軟刪除回收桶表。
8. **使用者帳號與家庭共享權限表（Users / Households / Roles）**：本系統為個人專用記帳本，不建立多使用者、登入認證或家庭成員共享關聯表。
